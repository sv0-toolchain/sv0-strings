# sv0-strings R0.4 gate review (SS-174 / SPEC §24.5)

**Verdict: PASS.** The safe POSIX.1-2024 Issue 8 `<string.h>` / `<strings.h>`
compatibility surface (`strings_posix2024`, `strings_legacy`,
`strings_locale`) is complete for R0.4. Every Issue 8 symbol is classified
exactly once by feature profile; every deterministic POSIX addition has a
green cross-backend fixture and, where it touches raw memory or search, a
differential check against real host libc; every host-locale / host-message
adapter is a typed fail-closed capability stub that never degrades to a
bytewise or synthesized substitute; and no safe module reads the ambient
process locale. **No new deviation** was introduced — D-4 … D-9 carry
forward unchanged (the flat `LocaleCompare` enum is a D-7 manifestation, not
a new decision).

## The R0.4 release claim (precise)

> `sv0-strings` R0.4 provides a **safe semantic-compatibility façade for
> ISO/IEC 9899:2024 (C23) §7.26 and IEEE Std 1003.1-2024 (POSIX.1-2024,
> Issue 8) `<string.h>` and `<strings.h>`**, on the C backend and the
> native VM, for the targets in `tools/catalogs/targets.tsv`
> (`linux-glibc-x86_64`, `darwin-arm64`).
>
> **Claimed now:** the C23 core (R0.3), the POSIX **Base** profile, the
> **deterministic CX** subset (`memmem`, `stpcpy` / `stpncpy`, `strlcpy` /
> `strlcat`, `strnlen`, `strtok_r`, `strdup` / `strndup`, and the
> POSIX-locale case fold `strcasecmp` / `strncasecmp` /
> `strcasecmp_l(_, _, Posix)`), and the **XSI** `ffs` / `ffsl` / `ffsll`.
> These are byte-deterministic under every host locale.
>
> **Explicitly NOT claimed (capability-gated):** the **host-locale /
> host-message CX** subset — `strcoll_l`, `strxfrm_l`, `strerror_l`,
> `strsignal`, `strerror_r` with a real message, and `strcasecmp_l` /
> `strncasecmp_l` with a `HostNamed` locale. These require the versioned
> host-capability ABI (toolchain slice **SS-U12**) and/or the FFI / host-call
> primitive (BL-103 / BL-104), both deferred. Until then each returns its
> typed "unavailable" value identically on every target, so an unsupported
> host service **blocks** that subprofile's claim rather than being silently
> skipped.
>
> **Removed interfaces** (`bcmp`, `bcopy`, `bzero`, `index`, `rindex`) are
> available only through an explicit `strings_legacy` import and contribute
> nothing to conformance.

## Deviations carried into R0.4

No R0.4-specific deviation was registered. The POSIX façade rides on the
existing F0 / R0.2 / R0.3 set (`docs/f0-deviations.md`): **D-4** (concrete
result carriers), **D-6** (`string` by value), **D-7** (`CStr` / `CString`
are an owned `string`; an enum payload cannot hold a struct **or another
enum** — the reason `LocaleCompare` is flat), **D-8** (`CBuffer` is
`&mut [byte]`), **D-9** (scalar tokenizer cursor).

## Known toolchain limitations worked around (not deviations)

- **`<i64-expr> as usize` narrows through a 32-bit `int` temp** on the C
  backend (found in SS-170). `strings_posix2024::ffs_bits` takes `i64`
  instead of `usize` to avoid it; the VM backend is unaffected. Follow-up
  filed for the real sv0c cast-lowering fix.
- **A `match` expression returning an enum value, and an enum payload that
  is itself a user enum, mistype to `int`** on the C backend (D-7 zone).
  `LocaleCompare` is a flat unit-variant enum and the `_l` adapters use
  single-level statement-form `match` with `return` in each arm.

## SPEC-deferred out of R0.4

- **Real host-locale collation / transform** (`strcoll_l`, `strxfrm_l`, and
  the `HostNamed` arm of `strcasecmp_l` / `strncasecmp_l`) — needs the
  versioned host-capability ABI, **SS-U12** (SPEC UP-015 / OQ-005).
- **Real owned host error / signal messages** (`strerror_r` payload,
  `strerror_l`, `strsignal`, and `strings_c23::strerror`) — needs the FFI /
  host-call primitive, **BL-103 / BL-104**; `strerror` then becomes a thin
  `strerror_l(errnum, LocaleId::Posix)` wrapper.
- **POSIX-015 full closure** — a live CI leg exercising the whole profile on
  each declared target (Linux glibc is live now; Darwin is a local gate).
  **R1.**
- **SEC-011 thread-sanitizer** for the locale/message profile — lands with
  the real host service. **R1.**
- **HOST-007** capability manifest (both backends required per claimed
  function) — **R1.**
