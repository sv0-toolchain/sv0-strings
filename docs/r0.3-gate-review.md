# sv0-strings R0.3 gate review (SS-155 / SPEC §24.4)

**Verdict: PASS.** The safe C23 `<string.h>` façade (`strings_c23`) is
complete for R0.3: every C23 §7.26 core function has a disposition matching
Appendix A.2, an adapter-rationale entry, and (where its disposition is
`Adapted`) a green cross-backend fixture plus, for the raw-memory operations,
a differential check against real host libc. C23 requirements C23-001 through
C23-030 all pass or are explicitly gated by a matrix row; `strcoll` /
`strxfrm` / `strerror` are profile-gated capability stubs. No new deviation
was introduced across the whole track — D-4 / D-6 / D-7 / D-8 / D-9 carry
forward unchanged.

## Deviations carried into R0.3

No R0.3-specific deviation was registered. The C23 façade rides on the
existing F0/R0.2 set:

- **D-4** — concrete result carriers (`CopyResult`, `ConcatResult`,
  `MemccpyReport`, …) instead of a generic `Result<T, E>` (lowering-side
  monomorphization gap).
- **D-6** — text APIs take `string` by value (sv0 has no surface `&string`).
- **D-7** — `CStr` / `CString` are an owned `string` (an enum variant with a
  struct payload does not lower on the C backend).
- **D-8** — `CBuffer` is its backing `&mut [byte]`; first-NUL recomputed.
- **D-9** — scalar tokenizer cursor (`pos: usize`), and `strtok`'s resume
  offset points *at* the not-yet-consumed separator (observable only when
  the separator set changes exactly at that boundary).

## SPEC-deferred out of R0.3

- **`strcoll` / `strxfrm`** real implementations — R0.4, BL-080 (explicit
  host locale capability). `strxfrm_size` shape is already in place.
- **`strerror`** real owned host-error adapter — SS-169 / BL-082.
- **SEC-011** thread-sanitizer for the locale profile — lands with the R0.4
  locale service.
- **TEST-017** recorded fuzz corpus / iteration budget on pure + accelerated
  paths — R1. R0.3 ships a bounded deterministic sweep (`test/fuzz/`,
  160 rounds) as the C23-019 evidence.
- **C23K-002 / C23K-003** — `Future` (an Annex K profile is not built).
