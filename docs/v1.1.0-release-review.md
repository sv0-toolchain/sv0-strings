# sv0-strings `v1.1.0` release review

**Verdict: PASS.** `v1.1.0` is the first release after `v1.0.0` (the R1 sign-off,
`docs/r1-gate-review.md`). It closes every slice that was still tracked after R1
and changes no requirement's coverage for the worse. The `v1.0.0` release claim
is unchanged except where this document says otherwise.

## What changed since `v1.0.0` (the claim delta)

| area | `v1.0.0` | `v1.1.0` |
|---|---|---|
| `fill_explicit` / `memset_explicit` | not exported; `BYTE-010` blocked, compile-fail probes pin the absence | exported; stores are non-elidable on C (`volatile`) and on the VM (dedicated builtin id); `BYTE-010` / `C23-014` done |
| POSIX-locale collation and transform (`strcoll`, `strxfrm`, `strcoll_l`, `strxfrm_l`, `strxfrm_l_size`, `strings_locale`) | fail-closed stubs, always `Unsupported` | real for `LocaleId::Posix` on both backends (bytewise collation, ASCII fold, no host call); `POSIX-008/009`, `HOST-002/003/004` done |
| Named locales (`LocaleId::HostNamed`) | `Unsupported` | `Unsupported` (unchanged, not started) |
| Host message text (`strerror*`, `strsignal`) | fail-closed stubs | fail-closed stubs (unchanged; needs an FFI host-call primitive) |
| Raw C ABI (`strings_unsafe_abi`) | empty stub module | real `#[extern_c] strlen` binding, feature-gated, external-linkage tested (`ARCH-006`) |
| C Annex K | excluded | declined permanently (`docs/annex-k-decision.md`) |
| Unicode algorithms | out of scope, unrecorded | recorded as a separate future package (`docs/unicode-package-scope-decision.md`) |

## Compatibility statement

Six former stubs changed return type (exact signatures in `CHANGELOG.md`,
"Changed"). They were documented as fail-closed capability stubs from `v1.0.0`
(`docs/locale-and-host-capabilities.md`), so this is released as a minor
version. A caller that matched on the old single-variant `HostCapability`
result must update that `match`. Every other public signature is unchanged.

`strings_locale`'s public functions are `locale_`-prefixed rather than SPEC
section 17.1's bare names, and `LocaleOpen::Opened` carries a `usize`
capability id rather than a `Locale` struct. Both are toolchain-driven
(`docs/f0-deviations.md` D-11 and D-4).

## Not claimed

- **Named-locale collation/transform.** `HostNamed` returns `Unsupported`.
  Registered exception `PERF-007` stays open for exactly this case; for the
  POSIX locale it is satisfied (the transform writes into the caller's buffer
  and never allocates; `strxfrm_l_size` is the tested size query).
- **Host error/signal message text** (`strerror`, `strerror_r`, `strerror_l`,
  `strsignal`). Still `Unavailable` / `Unsupported` everywhere.
- **`pub` visibility enforcement (`UP-025`, D-2), `no_alias` length upgrade
  (`UP-006`, D-5), single-allocation `CStr` concat (`PERF-004`, D-10).** Open
  registered exceptions, unchanged.
- **The `volatile` guarantee is verified on one compiler pair.** The
  dead-code-elimination regression fixture (sv0c `test/dce-stress/`) passes on
  clang/AArch64 and gcc/x86-64. On both, `sv0_fill_explicit`'s stores would
  also survive through the runtime's global slice table even without
  `volatile`, so the fixture proves the stores survive today but cannot detect
  a hypothetically dropped `volatile` on those compilers. The guarantee itself
  rests on the C standard's rule for `volatile` accesses.
- Everything `docs/r1-gate-review.md` already lists as out of scope.

## Toolchain requirement

This release requires an `sv0c` with the `fill_explicit` intrinsic (`442d9e54`)
and `&StructType` support (`4918818b`), and an `sv0vm` with builtin id 37
(`91fbc9d`). The pinned revisions are in `tools/catalogs/release_manifest.tsv`
and in the parent `sv0-toolchain` gitlink.
