# R0.1 gate review (SS-111 / SPEC §24.2)

Status: **PASS**, with `fill_explicit` remaining `Blocked` as §24.2 permits.

Backend results are hard-failing: every fixture below is asserted on **both**
the native C executable path and the native VM path by
`sv0-strings/scripts/test --backend=both --dir=test` (BACKEND-009). At the time
of review: **18 / 18** cases pass on both backends.

```sh
SV0_TOOLCHAIN_ROOT=<sv0-toolchain checkout> \
  sv0-strings/scripts/test --backend=both --dir=test
sv0-strings/scripts/check          # catalogs + doc fences, no toolchain
```

## Deviations carried into R0.1

Recorded in `docs/f0-deviations.md` (D-1..D-5); none affect a `BYTE-*` or
`ASCII-*` result:

- `copy` / `move_within` return **concrete carriers** (`CopyResult`,
  `MoveResult`) instead of `Result<_, BufferError>` — a structured error in a
  generic `Result` Err slot does not lower on the C backend (D-4 / toolchain
  T0-2d, an M5 prerequisite). Semantics and error information are unchanged.
- The `no_alias` interval-idiom decision (D-5) was **not exercised** by the R0.1
  byte core: `copy` is the non-overlapping fast path and `move_within` uses
  direction selection, so neither needs an overlap predicate.
